# 示例 1：深度研究工作流设计

## 场景描述

用户需要系统性地研究"Transformer架构的演进"这个主题，从基础概念到最新进展，包括：
1. 全面的知识梳理
2. 个性化的学习路径
3. 通俗化的讲解材料
4. 深度的技术分析

工作流编排家需要设计一个高效的多灵魂协作工作流来完成这个任务。

## 用户请求

```
召唤 [B-04] 工作流编排家，

我需要深入研究"Transformer架构的演进"，包括：
- 从原始论文到最新变体的完整演进路径
- 易于理解的学习材料
- 技术深度分析和关键创新点
- 可以分享给团队的完整报告

请为我设计一个完整的研究工作流。
```

### 第四部分：工作流配置文件

```yaml
# ============================================================
# Transformer演进研究工作流
# 版本: 1.0
# 创建时间: 2025-10-21
# 设计者: [B-04] 工作流编排家
# ============================================================

workflow:
  id: transformer-evolution-research
  name: "Transformer架构演进深度研究工作流"
  version: "1.0"
  description: |
    系统性研究Transformer架构从原始论文到最新变体的完整演进，
    产出包含通俗讲解、深度分析和可视化的完整研究报告。

    适用场景：
    - 技术主题的系统性研究
    - 需要多层次输出（通俗+专业）
    - 团队知识分享

  # 输入参数
  inputs:
    - name: research_topic
      type: string
      required: true
      description: "研究主题"
      default: "Transformer架构演进"

    - name: learner_background
      type: string
      required: false
      description: "学习者技术背景"
      default: "有深度学习基础"

    - name: include_visuals
      type: boolean
      required: false
      description: "是否包含可视化内容"
      default: true

  # 输出定义
  outputs:
    - name: final_report
      type: document
      description: "完整的研究报告（Markdown格式）"

    - name: team_presentation
      type: document
      description: "团队分享版本（简化版）"

    - name: quick_reference
      type: document
      description: "快速参考指南"

    - name: visualizations
      type: images
      description: "可视化图表集合"

  # 工作流阶段
  stages:
    # 阶段1：知识勘探
    - stage: 1
      name: "知识广度勘探"
      description: "构建完整的知识地图和演进脉络"
      steps:
        - id: step-1-1
          name: "全局研究"
          soul: c-06
          action: comprehensive_research
          inputs:
            topic: "${workflow.inputs.research_topic}"
            scope: "从原始论文到2025年最新变体"
            focus: ["关键创新", "技术分支", "应用场景"]
          outputs:
            knowledge_map: "结构化知识地图"
            key_papers: "关键论文列表"
            evolution_timeline: "演进时间线"
            innovation_points: "关键创新点列表"
          estimated_duration: "35min"
          on_error: abort

    # 阶段2：内容准备（混合执行）
    - stage: 2
      name: "学习路径与内容准备"
      description: "设计学习路径并准备多层次内容"
      steps:
        - id: step-2-1
          name: "学习路径设计"
          soul: a-01
          action: design_learning_path
          depends_on: [step-1-1]
          inputs:
            knowledge_map: "${step-1-1.knowledge_map}"
            learner_background: "${workflow.inputs.learner_background}"
          outputs:
            learning_path: "个性化学习路径"
            milestones: "学习检查点"
          estimated_duration: "18min"
          on_error: abort

        - id: step-2-2
          name: "通俗化转译"
          soul: g-08
          action: simplify_concepts
          depends_on: [step-1-1]
          parallel_with: [step-2-3, step-2-4]
          inputs:
            technical_concepts: "${step-1-1.innovation_points}"
            target_audience: "技术团队（混合背景）"
          outputs:
            simplified_content: "通俗化讲解材料"
            analogies: "生动类比集合"
          estimated_duration: "28min"
          on_error: continue

        - id: step-2-3
          name: "深度技术分析"
          soul: c-04
          action: deep_analysis
          depends_on: [step-1-1]
          parallel_with: [step-2-2, step-2-4]
          inputs:
            papers: "${step-1-1.key_papers}"
            focus_areas: ["架构创新", "性能提升", "应用拓展"]
          outputs:
            technical_analysis: "深度分析报告"
            critical_insights: "批判性洞察"
            future_directions: "未来方向预测"
          estimated_duration: "45min"
          on_error: abort

        - id: step-2-4
          name: "知识可视化"
          soul: d-06
          action: create_visualizations
          depends_on: [step-1-1]
          parallel_with: [step-2-2, step-2-3]
          enabled: "${workflow.inputs.include_visuals}"
          inputs:
            evolution_timeline: "${step-1-1.evolution_timeline}"
            knowledge_structure: "${step-1-1.knowledge_map}"
          outputs:
            timeline_visual: "演进时间线图"
            architecture_diagrams: "架构对比图"
            infographics: "信息图表集"
          estimated_duration: "32min"
          on_error: continue

    # 阶段3：最终整合
    - stage: 3
      name: "最终整合与报告生成"
      description: "整合所有内容为完整报告"
      steps:
        - id: step-3-1
          name: "文档整合重构"
          soul: e-02
          action: integrate_and_restructure
          depends_on: [step-2-1, step-2-2, step-2-3, step-2-4]
          inputs:
            learning_path: "${step-2-1.learning_path}"
            simplified_content: "${step-2-2.simplified_content}"
            technical_analysis: "${step-2-3.technical_analysis}"
            visualizations: "${step-2-4.*}"
          outputs:
            final_report: "完整研究报告"
            team_presentation: "团队分享版本"
            quick_reference: "快速参考指南"
          estimated_duration: "28min"
          on_error: abort

  # 错误处理策略
  error_handling:
    global_strategy: abort  # 关键步骤失败则中止
    retries: 2
    retry_delay: 30s
    fallback:
      - if_step: step-2-4
        on_error: continue  # 可视化失败不影响主流程

  # 性能配置
  performance:
    estimated_duration: "95-120min"
    max_parallel_tasks: 3
    timeout: 180min
    resource_level: high  # 使用Opus级模型

  # 质量检查点
  checkpoints:
    - after_step: step-1-1
      validation: "knowledge_map必须包含至少15个关键节点"
      on_fail: abort

    - after_step: step-2-3
      validation: "technical_analysis必须覆盖至少10篇论文"
      on_fail: warn

    - after_step: step-3-1
      validation: "final_report字数不少于8000字"
      on_fail: warn
```

## 关键设计亮点

### 1. 并行优化
- 阶段2的3个内容准备步骤可并行执行
- 节省约40-50分钟时间
- 最大化资源利用效率

### 2. 容错设计
- 可视化步骤失败不影响主流程
- 关键步骤（研究、分析、整合）失败则中止
- 平衡了稳定性和灵活性

### 3. 质量保证
- 每个阶段都有明确的验证标准
- 设置多个检查点确保质量
- 输出的最小标准明确定义

### 4. 参数化复用
- 可轻松调整研究主题
- 支持不同的学习者背景
- 可选的功能模块（如可视化）
